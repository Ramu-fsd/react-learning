# Contributing and Updating This Learning Repository

This repository is primarily a personal learning portfolio, but the following conventions keep it consistent.

## Folder conventions
- Keep each project self-contained when it has its own build/run lifecycle.
- Include a README with purpose, prerequisites, setup, run instructions and limitations.
- Keep architecture notes close to the project they describe.
- Use descriptive, numbered folder names to preserve learning order.

## Code conventions
- Prefer TypeScript for application examples unless a JavaScript exercise is specifically about JavaScript.
- Use clear component and variable names.
- Avoid committing secrets, `.env` files, personal data or production endpoints.
- Include loading, empty and error states for API-driven screens.
- Add tests for important business behavior.

## Documentation conventions
- Explain what the example demonstrates.
- Include setup and execution steps.
- Document architectural trade-offs.
- Clearly identify synthetic data and non-production limitations.
- Keep author and portfolio links consistent.

## Before publishing
- Review the README and folder structure.
- Check that no credentials or sensitive data are included.
- Run the relevant build and tests when practical.
- Verify that project-specific prerequisites are documented.
